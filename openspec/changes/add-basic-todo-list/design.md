# Design

## Context

專案目前只有 OpenSpec 設定，沒有程式、測試工具或既有規格。動機見 proposal.md；操作契約見 specs/todo-list/spec.md。採用原生瀏覽器功能，需能直接開啟 HTML，無須安裝套件。本設計釐清初始資料格式、儲存錯誤與安全文字呈現方式。

## Goals / Non-Goals

**Goals:**
- 將頁面結構、視覺樣式與狀態邏輯分為三個小檔案，保持可直接開啟與閱讀。
- 以單一記憶體清單驅動畫面，讓保存失敗不阻斷操作。

**Non-Goals:**
- 不加入模組打包、第三方 UI 元件、多分頁同步、資料匯入匯出或儲存資料版本遷移機制。

## Decisions

1. **檔案分工與執行方式**：根目錄使用 `index.html`、`styles.css` 與以 `defer` 載入的普通 `script.js`，搭配相對路徑與系統字型。不用 ES module、fetch 或外部 CDN，避免直接開啟檔案時的額外限制。相較全部塞在 HTML 中，分檔較易維護且不增加工具依賴。
2. **資料模型**：記憶體為有序陣列，每項為 `{ id, text, completed }`。id 是建立後穩定且在清單內唯一的字串，text 為 trim 後非空字串，completed 為布林值；以 id 定位項目，避免同名待辦互相影響。新增時檢查 id 是否重複，不依賴僅以時間戳記作識別。
3. **保存流程**：固定使用 `basic-todo-list:v1` localStorage key，保存 JSON 陣列。啟動時在 try/catch 中讀取、解析並驗證陣列及所有欄位與 id 唯一性；缺少 key 視為空清單，格式錯誤則整份拒收並提示。每次變更先更新記憶體與畫面，再嘗試保存。相較把 localStorage 當即時唯一來源，此流程能在儲存被封鎖時繼續操作。成功寫入後可清除先前保存失敗的提示；不主動清除其他 key。
4. **呈現與互動**：原生 form、具 label 的文字輸入框、ul/li、checkbox 與 button；以 `textContent` 放入待辦文字，避免使用者內容變成 HTML。提交走 form submit，使用穩定 id 進行狀態更新。提供狀態訊息區與空清單提示，完成項目以刪除線搭配勾選表示。更新清單時保留合理焦點：新增後回到輸入框，切換後保留該 checkbox，刪除後移到下一項、上一項或空清單的輸入框。
5. **版面**：繁體中文單欄卡片，限制最大寬度、小螢幕留出邊距；長文字允許任意換行，控制項避免被擠壓，保留清楚焦點樣式。不使用固定清單高度，以自然頁面捲動支援長清單。
6. **驗證方式**：以規格場景進行瀏覽器手動驗收，涵蓋 localStorage 正常與異常、鍵盤及窄視窗。此規模不新增測試框架；README 記錄開啟方式、驗收步驟及儲存限制。

## Risks / Trade-offs

- [file:// 的 localStorage 行為依瀏覽器而異] → 直接開啟仍須可操作；若無法保存則顯示提示，README 提供以靜態 HTTP 伺服器開啟的選項，驗收保存時保持相同來源與路徑。
- [瀏覽器資料被清除或私人模式結束後遺失] → README 說明這是本機資料，無跨裝置備份。
- [損壞的保存資料無法還原] → 明確提示並以空清單繼續，下一次使用者操作成功保存時覆寫該 key，不自動嘗試修復。
- [多分頁操作可能覆寫彼此] → 本次以單頁使用為前提，不加入同步複雜度。

## Migration Plan

無既有資料與部署流程，新增靜態檔案即可使用。回退時移除新增應用檔案；localStorage key 可留存，無需修改其他瀏覽器資料。
